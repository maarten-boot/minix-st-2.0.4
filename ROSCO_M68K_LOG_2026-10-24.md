## Follow-up 101: proc_vir2phys() maps text addresses to the shadow

User:
> yes please continue  (proc.h, memory.c and tty.c approved)

* **Cause** (src/kernel/proc.h:123, found for the catalogue, Follow-up
  99): the SHADOWING proc_vir2phys() added the shadow offset to every
  address, text too, the bug the umap() fix removed (2026-10-18). Text
  (string constants, const data) is not shadowed, so a shadowed process
  that wrote a constant to a terminal sent bytes from where its text
  would be in the shadow. Used by console/tty00 and pty output, pty
  reads, tty input, /dev/mem and the disk driver.
* **Fix:** the macro adds the offset only for addresses at or above the
  data segment (as umap()); the callers that used it as a base
  (`proc_vir2phys(p, 0) + addr`: roscdisk.c, memory.c, tty.c in_transfer)
  now map each address. Marked `rosco:`.
* **Test:** new src/rosco/test/tshadow2.c (test Makefile, sdproto): the
  parent writes a const 1K buffer to the pty slave /dev/ttyp3 (raw), a
  forked child reads it from /dev/ptyp3 and compares; the pty takes 128
  bytes at a time, so the parent waits in FS while the child in the same
  slot runs and the clock task shadows the parent. Old kernel: "failed:
  100 of 200 chunks wrong", "250 of 500"; fixed: ok, ok.
* Images rebuilt (115200 and sdfat115.img, then 38400). MAME over SLIP:
  tshadow2, tshadow, tsigcc, tsymexcl ok; ping, /dev/ttyp0 600; from an
  ast login all 40 tests and sh1, sh2 ok; no panic, "sig=", "Stack low"
  or Memory fault. The new compiler warnings are in upstream code.
* r68k (address errors) with the fixed kernel, the full suite from an
