* **SLIP on the board works**, both ways (user).
* **The shell "hangs":**
  * Reproduced in MAME: after any command with a non-zero exit status
    (`false`, `dosdir` without arguments, `life` ended with Ctrl-C, ...)
    there was no prompt. The shell did read and run the next command.
  * Cause: Minix's ash shows `PSE` instead of PS1 after a failed command
    (parser.c), and PSE is unset by default, which gives an empty prompt.
    Not a fork/exec problem.
  * Fix: `cmds/ash.patch` (applied to the copy in obj/ash) uses PS1 while
    PSE is unset.
  * Earlier sessions with an "expect #" that timed out after an error
    message were this, too.
* **man: "nroff: No such file or directory":**
  * ash has a default PATH (`:/bin:/usr/bin`) but does not export it; the
    old sh did. man runs nroff with execvp(), which only searched the
    current directory without $PATH.
  * In MAME, man worked in Follow-up 37 because root's shell was still
    the old sh then.
  * Fix: /etc/profile and /etc/rc set and export
    `PATH=/usr/local/bin:/bin:/usr/bin` (as src/etc/rc does), also for
    cron and inet.
* **Checked in MAME** (fresh card):
  * the prompt comes back after false, ls of a missing file, dosdir,
    `sh -c 'exit 3'`, and life with Ctrl-C;
  * `man ls` formats the page.
* **elvis, ESC then ":"** (not reproduced):
  * Minix's ttyread() in elvis waits for the rest of an ESC sequence with
    alarm(keytime), keytime in tenths of a second but alarm() in seconds,
    and leaves the read with longjmp from the handler.
  * A test program for that path (three alarm/longjmp timeouts out of a
    raw read, then plain reads) works.
  * elvis in MAME, with a new `type` command in mamesession.py (keys
    without Return, Python escapes): `iabc` ESC `:wq`, the same after a
    long pause, and a second ESC after one that timed out followed by
    `:wq` at typing speed: all work.
  * elvis switches the terminal to application cursor keys (`ESC [?1h
    ESC =`), so the terminal program may matter. Asked the user which one.
* **Noted for later:** go through the code of all tools for obvious errors
  and improvements (spec, open items).
* **Network tools** (telnet, rcp, ftp, ftpd, netcat): not started, see
  the reply.
* **Default card rebuilt** (38400).

* **New:**
  * rsh, rcp, rlogin and in.rshd (commands/simple);
  * in.rlogind (commands/rlogind, on the ptys);
  * `nc`, rosco's own small netcat (`src/rosco/cmds/nc.c`): `nc host
    port`, `nc -l port`, -v. A child copies stdin to the connection and
    shuts down the sending side at EOF; the parent copies the connection
    to stdout (Minix has no select).
  * rc.net.slip starts `tcpd shell /usr/bin/in.rshd` and `tcpd login
    /usr/bin/in.rlogind`.
  * Trust by /etc/hosts.equiv and ~/.rhosts (root: /.rhosts), no
    passwords.
* **Stacks:** in.rshd 16kw (the kernel said "Stack low" with the ACK
  4kw), in.rlogind 8kw.
* **The execl(…, 0) bug** (then SIGSEGV in in.rshd):
  * execl() uses its own arguments as the argv array
    (lib/posix/_execl.c). With -mshort a bare `0` is a 2-byte int, not a
    4-byte null pointer, so the list was not terminated.
  * All execl/execlp/execle calls in the built sources were checked
    (`(char *) 0`, `(char *) NULL` and plain NULL, which is `(void *)0`,
    are fine).
  * Wrong ones: in.rshd.c:412, make/make.c:52 (make ran its commands like
    this and only worked when the next two stack bytes were zero),
    elle/eemain.c:406 and 423 (shell escapes), and zmodem/rz.c:1546 (no
    terminator at all).
  * `cmds/execl0.sed` rewrites them in copies in obj/fix (FIX0 in
    cmds/Makefile).
* **Checked in MAME:**
  * nc: `nc -l 7777` on the board received 5000 bytes from Linux with the
    same cksum (3432479490); `nc host 7778` reached a listener on Linux;
  * rsh from Linux as root (Python client from a privileged port):
    `uname -a; id; ls /usr/ftp`;
  * on the board: `rsh rosco echo one`, rcp to and from rosco (cmp the
    same), rlogin rosco (root on /dev/ttyp0 without a password through
    /.rhosts, exit closes);
  * full test suite (make is rebuilt): tshadow, texecl, troscorun, all 40
    tests, sh1, sh2.
  * One run gave "rcp: unable to ioctl(NWIOTCPCONN): Connection refused"
    right after an rsh, while the Linux side tested rsh as well; not
    reproduced in a separate run (rcp right after rsh, and later).
  * rlogin prints a protocol control byte (shown as `M-^P`) before the
    prompt: cosmetic.
* **Passwords:** root stays without one (easier for newcomers).
  **`ROSCO_M68K_USAGE.md`** (new, also on the card as
  `/usr/doc/README.rosco`):
  * logging in;
  * a table of what works without a password (console logins, su, rsh
    and rlogin only with trust files, anonymous ftp) and what does not
    (telnet, ftp as a user);
  * enabling SLIP, the services and tools, file transfer without a
    network, known limits.
* **32-bit int (question, assessed only):** feasible with m68k-elf-gcc
  without -mshort.
  * The C side of Minix 2.0.4 already runs with 32-bit int on the i386
    port (`_EM_WSIZE == 4` paths, message fields as int).
  * To redo:
    * the rosco assembly (kernel entry/klib, crtso, sndrec, setjmp,
      sigret, m68kmul), whose argument offsets assume 2-byte int;
    * the Minix-ST/ATARI-only C code;
    * MM, FS, the kernel and all commands rebuilt;
    * old Minix-ST binaries would no longer run;
    * an ACK platform with 4-byte int for cc on the board (ACK has
      m68020 / 4-byte-int code generation);
    * a full retest.
  * Gains: no 64K object limit, a 32-bit size_t, the normal libgcc, and
    no -mshort traps like execl(…, 0) (a bare 0 would be 4 bytes).
    Bigger software such as MicroPython becomes straightforward.
  * Costs: larger, somewhat slower code on a 68010 (32-bit multiply and
    divide in software).
  * Best done as a build option next to the 16-bit system, not a
    replacement.
* **Default card rebuilt** (38400).
