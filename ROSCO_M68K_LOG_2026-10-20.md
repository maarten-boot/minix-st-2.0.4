* **SLIP on the board works**, both ways (user).
* **The shell "hangs":**
  * Reproduced in MAME: after any command with a non-zero exit status
    (`false`, `dosdir` without arguments, `life` ended with Ctrl-C, ...)
    there was no prompt. The shell did read and run the next command.
  * Cause: Minix's ash shows `PSE` instead of PS1 after a failed command
    (parser.c), and PSE is unset by default, which gives an empty prompt.
    Not a fork/exec problem.
  * Fix: `cmds/ash.patch` (applied to the copy in obj/ash) uses PS1 while
    PSE is unset.
  * Earlier sessions with an "expect #" that timed out after an error
    message were this, too.
* **man: "nroff: No such file or directory":**
  * ash has a default PATH (`:/bin:/usr/bin`) but does not export it; the
    old sh did. man runs nroff with execvp(), which only searched the
    current directory without $PATH.
  * In MAME, man worked in Follow-up 37 because root's shell was still
    the old sh then.
  * Fix: /etc/profile and /etc/rc set and export
    `PATH=/usr/local/bin:/bin:/usr/bin` (as src/etc/rc does), also for
    cron and inet.
* **Checked in MAME** (fresh card):
  * the prompt comes back after false, ls of a missing file, dosdir,
    `sh -c 'exit 3'`, and life with Ctrl-C;
  * `man ls` formats the page.
* **elvis, ESC then ":"** (not reproduced):
  * Minix's ttyread() in elvis waits for the rest of an ESC sequence with
    alarm(keytime), keytime in tenths of a second but alarm() in seconds,
    and leaves the read with longjmp from the handler.
  * A test program for that path (three alarm/longjmp timeouts out of a
    raw read, then plain reads) works.
  * elvis in MAME, with a new `type` command in mamesession.py (keys
    without Return, Python escapes): `iabc` ESC `:wq`, the same after a
    long pause, and a second ESC after one that timed out followed by
    `:wq` at typing speed: all work.
  * elvis switches the terminal to application cursor keys (`ESC [?1h
    ESC =`), so the terminal program may matter. Asked the user which one.
