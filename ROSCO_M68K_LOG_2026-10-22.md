  * **mkdir:** `-p` copied the path into a 256-byte stack buffer at every

## Follow-up 77: group 2, batch 2: the rest of the file tools

* **L: du, df, stat, file, install, basename, dirname, pwd, sync, update,
  mount, umount, printroot** (fixes/simple/<tool>.c.patch for 9; dirname,
  sync, update and printroot needed no change):
  * **update was never started:** nothing synced the FS cache, so a reset
    or power off lost every write since the last explicit sync; /etc/rc
    now starts /bin/update (a file written with it running was on the
    card 45 s later; without it, not);
  * **mount/umount:** setuid root, and FS checks only the effective uid,
    so any user could mount or unmount any partition anywhere (ast
    unmounted /dev/c0d0p3); now a user other than root needs read (and
    for rw write) access to the device and must own the directory; swap
    is root only;
  * **df:** a mount point of 128-255 characters in /etc/mtab smashed the
    stack (pc=61626364); being setuid root with seteuid = setuid, one
    unmounted device dropped root for the rest of the arguments; the
    bitmaps were counted by bytes, not big-endian 16-bit words (a full
    1008-block file system showed 1002 used / 6 free);
  * **install:** text files came out double length (relo_size
    uninitialized on this "ATARI" build: 277 → 554 bytes); an
    uninitialized status; short writes and close errors ignored; `-g`
