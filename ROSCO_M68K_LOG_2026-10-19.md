## Follow-up 35: ask for the date at boot, with a timeout

Committed `5853f4d` (Follow-up 34).

User:
> commit this first, then add the date prompt with timeout

* `date -q` (as in Minix's `/etc/rc`) has no timeout and does not handle
  an empty answer. **New command `asktime`** (`src/rosco/cmds/asktime.c`,
  `/bin/asktime` on both roots):
  * shows the clock and asks for `[[MMDDYY]hhmm[ss]]` (GMT, as `date`
    takes it);
  * a valid answer is set by exec'ing `/bin/date`;
  * RETURN, a malformed answer, or no answer within `-t` seconds (an
    `alarm()` interrupts the read) keeps the clock;
  * on a timeout the half-typed input is flushed, so getty does not see it.
* **`/etc/rc`:** after `date \`cat /etc/stamp\``, it runs
  `asktime -t 30 </dev/console >/dev/console 2>&1`. INIT starts rc with
  stdin on /dev/null and output on /dev/log, hence the redirections.
* **Checked in MAME:**
  * answer `102026153000`: `Tue Oct 20 15:30:00 GMT 2026`, and cron
    runs;
  * no answer: "no answer, clock kept", then login.
  * The mamesession scripts still work unchanged: the emulator runs
    unthrottled, so the 30 seconds pass quickly.
* **Default card rebuilt** (38400).

## Follow-up 36: gzip

User:
> commit this first, then look at a gzip port

* **Source:** GNU gzip 1.2.4 (1993) from ftp.gnu.org. There is no signature
  for this release; the tarball's sha256 is
  `1ca41818a23c9c59ef1d5e1d00c0d5eaa2285d931c0fb059637d7c0cc02ad967`.
  The sources, COPYING, README, NEWS, ChangeLog, gzip.1 and algorithm.doc
  are in `src/rosco/gzip-1.2.4`, unchanged.
* **`cmds/gzip.patch`** (applied to a copy in `obj/gzip`, as with
  dosread) adds a ROSCO section to `tailor.h`. It uses the 16-bit setup
  of the MS-DOS port: `MAXSEG_64K` and `DYN_ALLOC`, plus `NO_SYMLINK`,
  `STDC_HEADERS`, `HAVE_UNISTD_H` and `DIRENT`.
* **`cmds/gzrosco.c`:**
  * `fcalloc()` gets the 64K window and the hash tables from `sbrk()` in
    16K chunks. With a 16-bit size_t, `calloc(32768, 2)` is 0.
  * `rosco_read()`/`rosco_write()` (`read`/`write` in the ROSCO section)
    move at most 16K per call. gzip reads 32K and writes its 32K window
    in one call, and FS takes a count of 32K as negative: the first
    build wrote only the 20-byte header ("Invalid argument"). gzip copes
    with short reads, so the buffer sizes, and with them the output,
    stay those of standard gzip.
* `/usr/bin/gzip` with links `gunzip` and `zcat`, `-S 400k` (304K of
  buffers). Also `/bin/uncompress` (a link to compress), which was
  missing.
* **Checked in MAME** (5MB, 115200):
  * gzip -9, -6 and -1 output of kermit, cawf and a 300K file (4
    binaries) is byte-identical to gzip 1.2.4 built on the host (and,
    at -9, to the host's current gzip). Minix `cksum` is the old 1003.2
    draft CRC, so the host values were computed with a Python copy of
    it.
  * gzip -v/-t/-l, gunzip, zcat of a pipe, gunzip of a compress `.Z`,
    and `tar cf - d | gzip` then `gunzip -c | tar xvf -` all work.
* **Speed** (emulated 10 MHz 68010, the 300K file):

  | | time | output |
  |---|---|---|
  | gzip -9 | 2:20 | 148021 |
  | gzip (-6) | 1:34 | 148250 |
  | gzip -1 | 1:01 | 158484 |
  | compress | 1:03 | 229964 |
  | gunzip | 0:22-0:33 | |

  At 38400 baud (about 3.8K/s), receiving .gz files and gunzipping them
  on the board pays off. For sending, gzip -1 is as fast as compress and
  compresses much better, but the compression time is close to what it
  saves on the line for binaries; text compresses better.
* **Default card rebuilt** (38400).

## Follow-up 38: ash

* **`commands/ash`** (the Minix 2.0.4 ash; its stock Makefile installs it
  as `/usr/bin/ash`) is built in `cmds/Makefile`. The sources are copied
  to `obj/ash`, and the generators run there on the build host (in the
  container), with `gcc -std=gnu89`:
  * the scripts mkbuiltins, mktokens and bltin/mkexpr;
  * mknodes, mksyntax and mkinit (`mkinit true ...` only writes init.c);
  * mksignames, with a `host/signal.h` that holds the SIG macros of the
    Minix `include/signal.h`, taken through the host cpp
    (`-nostdinc -dM`) with the target's defines. The table matches Minix
    (10 = "User signal 1", MAXSIG 22).
  * mksyntax depends on char signedness: char is signed for both gcc's.
  * mknodes: glibc's `stdin` is not a constant initializer, so
    `host/mknodes.c` drops `= stdin` (infp is always set by fopen).
  * Target flags: `-Dconst=` (main.c's `getenv(char *)`) and `-D__CC68__`
    (bltin/regexp.c's malloc declaration).
* **libedit:** ash has READLINE on, so `src/rosco/lib` builds
  `libedit.a` from `lib/editline` with the DEFS of its Makefile (ANSI
  arrows, termcap, history 100).
* `/usr/bin/ash` on the SD root (12kw, as in the ACK build). `/bin/sh` is
  still the old Minix shell.
